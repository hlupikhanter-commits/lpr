Вопрос: Почему /catalog/abc даёт 404, хотя в контроллере нет проверки на буквы?
Ответ: Проверка осуществляется на этапе сопоставления URL в routes/web.php модификатором ->whereNumber('id'), накладывающим регулярное выражение ^[0-9]+$. Строка 'abc' не является числом, поэтому маршрут не сопоставляется фреймворком, запрос не передаётся в контроллер, и Laravel немедленно возвращает 404 Not Found.

Наблюдение 4. POST-форма и механизм защиты CSRF

  • 1. Методы и коды двух запросов:
    1. POST /feedback → 302 Found (перенаправление на /feedback).
    2. GET /feedback → 200 OK (отображение формы с зелёным баннером успешной отправки).
    Почему их два: Использован паттерн Post/Redirect/Get (PRG), исключающий повторную отправку формы при обновлении страницы (F5).
  • 2. Удаление @csrf: Приводит к прерыванию запроса с кодом 419 Page Expired (исключение TokenMismatchException). Директива @csrf преобразуется в HTML в скрытый инпут <input type="hidden" name="_token" value="...">.
  • 3. Отправка текста <b>жирный</b>: Текст выводится как обычные строковые символы <b>жирный</b>, а не жирным начертанием. Конструкция Blade {{ session('status') }} автоматически применяет функцию htmlspecialchars(), экранируя HTML-теги для предотвращения XSS-атак.

Ошибка 2. Ошибка декодирования кириллицы при фильтрации по родителю

  • Симптомы: При переходе по маршруту /catalog/owner/Смирнов+Алексей возвращался пустой список («Ничего не найдено»).
  • Причина своими словами: Браузер передавал пробел в пути как +. В контроллере строковое сравнение $pets->where('owner', $owner) сравнивало "Смирнов+Алексей" с "Смирнов Алексей" и не находило совпадений.
  • Способ устранения: В методе CatalogController::byOwner добавлено декодирование: $owner = urldecode($owner);, что обеспечивает точное соответствие при любых вариантах кодирования пробелов в URL.

6. Ответы на контрольные вопросы

  1. Опишите путь запроса GET /catalog/2 в вашем приложении: какие файлы участвуют и в каком порядке.
    Браузер отправляет запрос GET /catalog/2 → единая точка входа public/index.php → автозагрузка vendor/autoload.php и создание экземпляра фреймворка в bootstrap/app.php → выполнение конвейера веб-middleware → сопоставление маршрута в routes/web.php (правило whereNumber('id')) → вызов метода CatalogController::show(2) → выборка записи из pets() через collect()->firstWhere('id', 2) → передача данных в resources/views/catalog/show.blade.php → компиляция Blade вместе с resources/views/layouts/app.blade.php → возврат готового HTML-документа со статусом 200 OK.
  2. Почему .env не хранится в Git? Для чего нужен .env.example?
    .env хранит секретные ключи, пароли к базе данных и реквизиты сред разработки, публикация которых ведёт к утечке данных. Кроме того, у разных разработчиков конфигурации окружения индивидуальны. Файл .env.example служит публичным шаблоном, описывающим требуемый набор переменных без указания реальных секретных значений.
  3. Чем config('lab.code') отличается от env('LAB_CODE')? Что изменится после команды php artisan config:cache?
    env() напрямую читает значение из файла .env или переменных окружения операционной системы. config() читает значения из репозитория конфигурации Laravel. После выполнения config:cache все настройки кэшируются в один файл, чтение .env прекращается, и прямые вызовы env() начинают возвращать null. Любые правки в .env не применятся до сброса кэша командой php artisan config:clear.
  4. Чем отличаются $request->query('x') и $request->input('x')?
    $request->query('x') считывает параметр строго из строки запроса URL (после знака ?). Метод $request->input('x') является универсальным: он ищет параметр сначала в теле запроса (POST form data, JSON), а при отсутствии — в строке запроса.
  5. Почему после POST-формы возвращается redirect(), а не view()?
    Это архитектурный паттерн Post/Redirect/Get (PRG). Если вернуть view(), страница останется результатом POST-запроса, и при обновлении (F5) браузер повторно отправит форму, вызывая дублирование данных. Редирект переводит браузер в безопасный GET-запрос.
  6. Что такое CSRF-атака и как @csrf от неё защищает?
    CSRF (Cross-Site Request Forgery) — атака, при которой сторонний сайт выполняет нежелательный запрос к целевому ресурсу от имени авторизованного пользователя через автоматически передаваемые cookie. Директива @csrf внедряет скрытый токен _token, известный только серверу и сессии пользователя; сторонний сайт не может его прочесть, и запрос без валидного токена отклоняется с ошибкой 419.
  7. Что будет, если в вашем web.php убрать whereNumber('id') и открыть /catalog/abc?
    Строка 'abc' будет расценена как значение параметра {id}. Запрос перейдёт в контроллер CatalogController::show($id), где из-за строгой типизации int $id произойдёт приведение к 0 или ошибка типизации. Поиск вернёт null, и контроллер сам вызовет abort_if(true, 404). Однако фильтрация в роутере предпочтительнее, так как отсекает некорректные запросы на раннем этапе.
