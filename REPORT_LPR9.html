3. Журнал ошибок

Ошибка 1: Ошибка подключения PDO к MySQL-серверу (Connection refused 10061)

Симптом: При выполнении php artisan migrate консоль возвращала исключение SQLSTATE[HY000] [2002] Can't connect to MySQL server on '127.0.0.1:3306' (10061).
Причина: В Open Server Panel 6 служба СУБД MySQL-8.4 привязана к сетевому адресу 127.0.1.31, а сам рабочий процесс mysqld.exe не был запущен в фоновом режиме.
Исправление: Запущен фоновый демон mysqld.exe с файлом конфигурации my.ini, создана БД lpr_meshitbayev, а в .env настроен адрес DB_HOST=127.0.1.31.

Ошибка 2: Ошибка скрипта Composer в PowerShell (Could not open input file: composer.phar)

Симптом: Команда composer require в терминале падала с ошибкой Could not open input file: composer.phar.
Причина: В composer.bat путь сформирован через переменную среды %COMPOSER_HOME%, которая по умолчанию не была инициализирована в новой сессии PowerShell.
Исправление: В файл composer.bat добавлена директива задания пути по умолчанию @if "%COMPOSER_HOME%"=="" set "COMPOSER_HOME=C:OSPaneldataPHP-8.4defaultcomposer", а путь к PHP добавлен в переменную окружения PATH.

5. Ответы на контрольные вопросы

  1. Что хранится в таблице migrations? Что такое batch и что делает php artisan migrate:rollback?
    В таблице migrations регистрируются имена всех успешно выполненных миграций и номер пакета (batch), в котором они были применены. Поле batch группирует миграции, примененные за один вызов команды php artisan migrate. Команда migrate:rollback отменяет (метод down()) только миграции последнего пакета (партии) и удаляет их из таблицы.
  2. Почему нельзя изменять уже выполненную миграцию?
    Потому что Laravel сверяется с таблицей migrations и повторно её выполнять не станет. Изменение накатанной миграции нарушит версионирование схемы БД между разработчиками и продакшеном. Любые изменения существующей структуры таблиц должны делаться созданием новой отдельной миграции.
  3. От чего защищает $fillable? Приведите пример для вашей модели.
    Защищает от уязвимости Mass Assignment (массового присвоения), предотвращая перезапись служебных или чужих полей (id, role, чужие FK). Пример в модели Pet: разрешены только ['owner_id', 'name', 'description', 'species', 'birth_date', 'weight_kg', 'is_vaccinated'].
  4. Как Laravel по маршруту /albums/{album}/edit находит запись в БД? Что будет, если записи нет?
    Через неявное связывание моделей (Implicit Route Model Binding). Laravel ищет запись по первичному ключу: Album::where('id', $album)->firstOrFail(). Если записи нет, метод выбрасывает ModelNotFoundException, преобразуемый в ответ ошибки 404 Not Found.
  5. Чем $request->all() отличается от $request->validated()?
    $request->all() возвращает все пришедшие данные из запроса без проверки, а $request->validated() возвращает строго проверенные поля, объявленные в правилах rules() валидатора FormRequest.
  6. Что делает Rule::unique(...)->ignore($id) и что будет при редактировании без ignore?
    Исключает текущую редактируемую запись из проверки на уникальность. Если не указать ignore($id), валидатор посчитает саму же текущую запись дубликатом и заблокирует сохранение формы.
  7. Чем restrictOnDelete() отличается от cascadeOnDelete()? Какой вариант подходит для вашей предметной области по смыслу?
    RESTRICT блокирует удаление родителя при наличии дочерних записей. CASCADE автоматически удаляет всех связанных потомков. Для ветклиники по смыслу логичнее RESTRICT, чтобы случайно не стереть пациентов и их медкарты, однако для нечётного $N=11$ правилами работы строго реализован CASCADE.
